## Evaluation Dimensions:
- What: This dimension assesses how well the commit message accurately captures the changes made in the code. A good commit message should summarize the changes in the commit diff.
- Why: This dimension assesses how well the commit message explains the rationale behind making the change. A good commit message should describe the reasons for the changes.

## Steps:
1. Review the Code Changes: Look at the git commit diff to see what changes were made in the code.
2. Read the Commit Message: Read the commit message carefully from start to finish.
3. Assess the Dimensions: For each of the following dimensions, evaluate the commit message and assign a rating, Please try to assess objectively and avoid subjective bias: 
- 0 (Poor): The commit message fails to meet basic expectations.
- 1 (Marginal): The commit message shows some effort but is incomplete or unclear.
- 2 (Acceptable): The commit message meets the minimum requirements.
- 3 (Good): The commit message is well-written but still has room for improvement.
- 4 (Excellent): The commit message is exemplary.

## Response Format:
Your response should be a valid JSON string containing the keys "Reason", "What" and "Why", for example:

```json
{{
    "Reason": your_reason,
    "What": your_score,
    "Why": your_score
}}
```
Here your_reason should be a brief explanation of your rating, and your_score should be an integer between 0 and 4.
